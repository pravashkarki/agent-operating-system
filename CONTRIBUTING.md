# Contributing

This is a working operating model, not a manifesto. Changes are welcome when they come from use.

## What makes a good change

- One rule per pull request. A rule is easier to accept, argue, or revert on its own.
- Say what happened. The best justification is a short account of a real session where the current rule failed or was missing: what the agent did, what it should have done.
- Keep the shape. Rules are short imperative sentences grouped under a heading that says when they apply. No filler, no hedging, no em dashes.
- Generic, not personal. No names, clients, hostnames, local paths, or tool-account details. Placeholders like `<docs-root>` are fine.
- Add a line to `CHANGELOG.md` with the date and the reason.

## Adapting rather than contributing

Most people should fork and edit for their own setup; the model expects local project files to tighten it. Contribute back only what would hold for anyone running several agents with one owner.

## Retiring a rule

Propose removal the same way as an addition: which rule, why it no longer matches reality, and what replaces it (possibly nothing). See "Retiring A Rule" in the operating model.
